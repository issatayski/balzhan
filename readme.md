# Трекер портфолио — Архитектура 6B07310

Мини-сайт для отслеживания портфолио студента-архитектора. Данные лежат в Google Таблице,
сайт раздаётся с GitHub Pages, сервера нет — его роль выполняет Google Apps Script.

```
Сайт (GitHub Pages)  ⇄  Apps Script  ⇄  Google Таблица
```

Работает с телефона, помнит данные без интернета и досылает изменения, когда связь появляется.

---

## Настройка: 15 минут, три шага

### Шаг 1. Таблица и скрипт

1. Создайте новую Google Таблицу — название любое.
2. В меню: **Расширения → Apps Script**.
3. Удалите содержимое файла `Код.gs` и вставьте туда всё из `apps-script/Code.gs`.
4. Сохраните (Ctrl+S).
5. Вверху выберите функцию **`setupSheet`** и нажмите **Выполнить**.
   Google попросит разрешение — это нормально, скрипт ваш собственный. На экране
   «Google не проверил это приложение» нажмите «Дополнительные настройки» →
   «Перейти к проекту».
6. Появится сообщение «Готово: записано дисциплин — 51», а в таблице — лист «Трекер».

### Шаг 2. Публикация скрипта

1. В редакторе скрипта: **Развернуть → Новое развёртывание**.
2. Тип — шестерёнка слева → **Веб-приложение**.
3. Настройки:
   - Запуск от имени — **Я**
   - У кого есть доступ — **Все** (Anyone)
4. Нажмите **Развернуть** и скопируйте адрес. Он выглядит так:
   `https://script.google.com/macros/s/AKfy.../exec`

Проверка: откройте этот адрес в браузере. Должен появиться текст, начинающийся с
`{"ok":true,"rows":[...`. Если так — серверная часть работает.

> **Важно.** Каждый раз, когда вы меняете код скрипта, нужно делать
> **Развернуть → Управление развёртываниями → карандаш → Версия: новая → Развернуть**.
> Иначе сайт продолжит работать со старой версией.

### Шаг 3. Сайт на GitHub Pages

1. Создайте репозиторий на GitHub, например `portfolio-tracker`.
2. Загрузите в него `index.html`, папку `assets` и этот файл.
3. **Settings → Pages → Source: Deploy from a branch → Branch: main, папка `/ (root)`** → Save.
4. Через пару минут сайт будет по адресу
   `https://ВАШ-ЛОГИН.github.io/portfolio-tracker/`
5. Откройте его, вставьте адрес из шага 2 и нажмите «Подключить».

Адрес скрипта сохраняется **только в браузере**, в коде сайта его нет. Поэтому репозиторий
можно держать публичным. На каждом устройстве адрес вводится один раз.

## Как этим пользоваться

Четыре квадратика напротив каждой дисциплины — это четыре вещи, которые нужно сохранить:

| | что означает | что именно класть |
|---|---|---|
| **И** | исходники | `.dwg`, `.pln`, `.rvt`, `.max`, `.psd` |
| **Ф** | фото подачи | планшет целиком, макет со всех сторон |
| **П** | финальный PDF | не ниже 300 dpi |
| **О** | описание | 3–5 предложений: задача, идея, что было сложно |

Нажатие на строку раскрывает карточку: название работы, оценка, ссылка на папку
Google Диска, заметки. Всё сохраняется само, кнопки «Сохранить» нет.

Фотографии складываются в Google Диск обычным приложением, а в карточку вписывается
ссылка на папку. Загрузка файлов прямо с сайта сознательно не сделана — она требует
отдельной авторизации и ломается чаще, чем работает.

## Если что-то не так

**«Не получилось прочитать таблицу»** — в развёртывании стоит доступ не «Все». Откройте
Управление развёртываниями и поменяйте.

**Изменения не доходят до таблицы** — в штампе сверху вместо времени будет «ждёт N».
Значит нет связи или скрипт недоступен. Данные не потеряются: они лежат в браузере и
уйдут при следующем подключении.

**Правки в самой таблице** видны на сайте после нажатия «Обновить».
Столбцы `ID`, `Курс`, `Семестр`, `Дисциплина` руками лучше не трогать — по `ID`
скрипт находит строку.

## Состав

```
index.html            разметка
assets/styles.css     оформление
assets/app.js         логика: кэш, очередь отправки, отрисовка
apps-script/Code.gs   серверная часть для Google Apps Script
```

Ни сборки, ни зависимостей, ни npm — GitHub Pages просто раздаёт эти файлы.
